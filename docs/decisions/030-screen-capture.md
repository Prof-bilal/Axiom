# ADR 030: Screenshots and screen recording use grim and wf-recorder, driven by the shell

Status: Proposed. The capture bar is implemented; `grim` is verified on a host Hyprland, `wf-recorder`
and the packaging are not yet verified in QEMU (see Verification).

## Context
The desktop needs a capture bar (Print key): image of a region, a window area or the whole screen, and
video of a region or the whole screen, as in the reference design. The session is Wayland, so an
application cannot read other windows' pixels directly; capture has to go through the compositor.

## Decision
- Capture goes through the compositor's `wlr-screencopy` protocol with two small command-line tools,
  `grim` (image) and `wf-recorder` (video), plus `wl-clipboard` (`wl-copy`) to put the image on the
  clipboard. All three are unprivileged, daemon-free, and in the official Arch repositories.
- The Axiom Shell owns the interface (`shell/src/capture/CaptureBar.qml`): mode bar, region selection,
  timer, microphone toggle and recording indicator. It only builds the argument list and runs the tool;
  every command is an argv array, and the output path is generated by the shell (`~/Pictures/Screenshots`,
  `~/Videos`), never taken from user input.
- No new daemon and no privileged component. No capture happens without an explicit user action in the bar,
  and a recording shows a visible indicator with a Stop button for as long as it runs.
- Audio is off by default. The microphone toggle passes `--audio` to `wf-recorder`, which uses the default
  PipeWire input.

## Alternatives considered
- `Quickshell.Wayland.ScreencopyView`: fine for screenshots without extra packages, but cannot record
  video, so a second path would be needed anyway.
- `xdg-desktop-portal` screencast (PipeWire): the right route for sandboxed apps, and still needed for
  browsers. The shell is trusted session code, so the direct protocol is simpler and works without a
  portal dialog. Portal screencast for third-party apps is a separate concern.
- `ffmpeg x11grab`/`kmsgrab`: X11 or root-only; rejected.

## Consequences
- Adds three small packages to the ISO (`grim`, `wf-recorder`, `wl-clipboard`).
- Window capture is a crop of the screen to the window's rectangle, so anything on top of the window
  appears in the image. A per-window capture needs the toplevel-capture protocol and is not done.
- Recording quality and CPU cost under software rendering (QEMU) are not representative of real hardware.

## Rollback
Remove the three packages and the `Print` / `Super+Shift+S` bindings; nothing else depends on them.

## Verification
- Host: `grim -g "x,y wxh"` captures a region under Hyprland.
- QEMU (pending ISO rebuild): bar opens, region capture writes a PNG, recording writes an MP4 and Stop
  finishes the file.

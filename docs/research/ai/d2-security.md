## 1. Warden (/home/abullah/Projects/Warden)
What it does (code): Go CLI (module github.com/warden-sandbox/warden, go 1.24, deps only yaml.v3, go-toml, x/sys). Spawn-time wrapper: `warden run --policy p.yaml -- cmd`, `trace`, `init` (starter policy from observed accesses), `doctor`, `logs`, `gateway`, `mcp`, `agent` (sanitized agent workspace: secrets in dotenv/JSON/YAML/TOML replaced with placeholders, sanitized diff + human approval before applying to real project, supervisor-owned credential broker socket). Packages: policy, sandbox{linux,darwin,windows,docker}, proxy (egress), envfilter, audit, mcpproxy/mcpbridge/mcpserver/gateway, attestation (Ed25519 evidence), container (Docker/K8s manifest + seccomp profile generation for containers only), agentworkspace, selfupdate, packs.
Linux backend (internal/sandbox/linux/linux.go, ~1300 LOC incl. tests): bubblewrap with --unshare-user/ipc/pid/net, --disable-userns, --die-with-parent, fresh /dev,/proc,/tmp tmpfs, ro-bind runtime base, deny-by-default bind mounts (ungranted = absent), `setpriv --nnp`, strace (-f, %file,%network) run outside sandbox -> JSONL audit imported after exit; egress via host loopback HTTP(S) proxy + in-sandbox bridge, hostname allowlist before DNS, private/loopback/link-local refused; env allowlist; memory limit by RSS sampling every 25 ms + wall-clock kill. Refuses to run if bwrap/setpriv/strace missing.
Maturity: 202 commits (181 Prof-bilal, a few others), last commit 2026-11-03, tag v0.2.0-beta.4-4-g65680c3; ~12.9k files incl. landing/video/shots assets; Go core ~102 non-test files, 59 test files; CI workflows ci.yml, release.yml, test-warden-action.yml; proof harness testdata/proof/run-proof.sh. Pre-1.0 by its own words. Axiom docs record v0.1.17 stable (2026-09-14) at Axiom pin f7c9793; the repo is now ahead (beta.4+); re-pin required.
Stack/runtime: Go static binary (npm wrapper `warden-sandbox-cli` for distribution). Linux needs bwrap, setpriv (util-linux), strace, unprivileged user namespaces working. No daemon in run mode (gateway/mcp modes are per-use processes). No root needed on Linux; Windows needs admin (not relevant).
License: MIT (LICENSE: "Copyright (c) 2026 Warden contributors"). Note copyright holder wording "contributors" with a few non-owner authors (HusnainMaroof 11, Abdullah 8 commits) - confirm contributor rights/DCO before shipping inside Apache-2.0 Axiom (MIT is compatible, but notices needed).
Threat model claimed vs enforced (SECURITY.md/docs/security.md, honest): 7 categories. Admitted gaps: symlinks inside granted paths not resolved/blocked; bwrap is trusted code; only HTTP/HTTPS egress intercepted (raw TCP/UDP just has no route in the netns, fine, but means no non-HTTP egress at all); no cgroups, no CPU limit; memory is sampled (overshoot possible); grandchildren outside tracked tree may escape limits; strace overhead unbenchmarked; strace temp files in /tmp race; HOME+~/.ssh policy-authoring footgun; `trace` is unsandboxed. NOT claimed/absent: seccomp filter on Linux native (only in container translation), Landlock (none), cgroups, eBPF. Not hardened against a determined local attacker (their words).
Known gaps (my reading): audit is post-hoc via strace (not preventive, not live, ptrace-based so bypassable by anything that detaches strace? strace runs outside as tracer of the setpriv/bwrap chain - -f follows children; a tracee cannot detach the tracer, but seccomp/ptrace interactions and PTRACE_TRACEME-style tricks are worth testing); audit integrity not signed/append-only (file mode 0600 only); no typed API; request_id correlation absent; policy format is YAML with a human-oriented model.

Policy format (internal/policy): YAML, KnownFields(true) strict: command[], filesystem{read[],write[],deny[] (glob, deny wins), protect_secrets}, network{allow[] hostnames}, env{allow[]}, limits{memory_mb,timeout_s}, mcp{...}, agent{...}. Supervisor-owned fields (ReadOnlyPaths, AgentSocket, AgentCwd) are yaml:"-" so policy input cannot set them (good pattern for Axiom).

Axiom view
(1) Warden disposition: viable as the Phase 11 "Shield" sandbox for untrusted tool/MCP workers on Linux, as a child process the Axiom executor launches. NOT as an authorizer. Realistic shape: Axiom executor builds a policy struct from the approved typed request, hands it to Warden's Go packages (internal/ -> must be exported as a pkg) or CLI, and gets structured result + audit refs.
(2) Axiom needs that Warden already provides: filesystem scopes (read/write/deny, absent-not-EACCES mounts), network host allowlist with DNS-after-allow, env allowlist/secret placeholders, MCP server confinement (mcpproxy/gateway; bwrap per server), JSONL audit, fail-closed refusal, wall-clock/mem limits, no_new_privs. Missing for Axiom: seccomp, Landlock (defense in depth, and needed when bwrap/userns unavailable), cgroups v2 limits/cancellation, D-Bus/portal socket guarantees tested, typed API, request/audit ID correlation, tamper-evident audit, symlink/TOCTOU safe path grants, non-HTTP egress policy.
(3) Conflicts with Axiom rules: needs unprivileged user namespaces (Axiom must keep that sysctl enabled and test it; Arch/hardened kernels may restrict) - a design fact, not a root requirement. strace requirement = ptrace dependency on a small image, overhead, and a hard-fail launch dependency (fits fail-closed but is heavy; consider dropping strace in favor of seccomp-notify/Landlock audit or an Axiom-side log). npm distribution/Node wrapper irrelevant: use the Go binary only. selfupdate package = network use/auto-update path that must be disabled in Axiom. No root helper, no resident daemon on Linux (good). Windows/macOS/Docker backends = dead weight on the image; build with linux tags only. Egress proxy is a per-run host process: fine, but is "a generic proxy" the Axiom docs warn about - keep it bound to loopback/per-run socket, no reuse.
(3b) strace-based native audit shows what happened, not what was prevented; Axiom's "attribute actions, verify changes" rule is satisfied only if blocked-attempt records are machine-readable (they are JSONL; unverified completeness).
(4) Integration cost / path: Phase 11a (small): vendor as pinned source (go.mod replace or git subtree, Axiom is a Rust/other monorepo with Go side binary), CLI wrapper POC `warden run` driven by a generated YAML written to a root-owned? no - a per-run 0600 temp file in the user runtime dir; run bypass matrix E05/E22 in QEMU; fix gaps found. 11b (medium): export a pkg/ API (Execute(Envelope) Result per the sketch), add request_id/audit_id fields, class mapping; add seccomp (small allowlist, built from policy) and Landlock as second layer; cgroups v2 via systemd transient scope (systemd-run --user) for memory/CPU/cancel instead of RSS sampling. Later (Phase 12): agent-definition `sandbox:` profile -> policy generator, multi-session worker lifecycle, sanitized-workspace mode (`warden agent`) for coding agents, attestation evidence in the activity view.
(5) VERDICT: BUNDLE (conditional) - bundle as the default Linux tool/MCP-worker sandbox at Phase 11 only after the bypass matrix passes and a typed pkg API exists; until then it stays RESEARCH behind the existing gate. Reason: it already implements most of Axiom's wanted controls, is first-party MIT, small dependency surface, Go single binary, no daemon, fail-closed behavior matches Axiom rules, and it is the only candidate with MCP and secret-placeholder workspace features. It stays an enforcer behind Axiom policy; do not let its YAML be the authority format. Risk of lock-in to bwrap/strace is acceptable because the Axiom-side Envelope/Result is the stable contract, so the backend can be swapped (Landlock+seccomp+systemd).

## 2. ShieldCI (/home/abullah/Projects/ShieldCI)

(5) VERDICT: PORT-CONCEPT (Landlock spawn-time + learn-then-review policy). SKIP live eBPF, cloud, and server-product parts. Reason: license is proprietary and product scope is a different market; the reusable value is a small, well-scoped Landlock implementation and policy-learning rules, both first-party and re-derivable.

## 4. Conflicts summary and shared risks
- Axiom rule "every daemon justified": Warden run-mode has none (OK); Vorynex agent and ShieldCI control plane add daemons (reject).
- "Preserve Wayland/portal boundaries": none of the three test the Wayland socket, D-Bus session/system bus, portal, or ssh/gpg agent sockets inside the sandbox. WARDEN_INTEGRATION requires "no D-Bus, SSH/GPG agent" - verify bwrap actually omits $XDG_RUNTIME_DIR; Warden's fresh /tmp and absent mounts suggest yes (UNVERIFIED).
- "Core works without cloud AI/network": Warden is local; ShieldCI hosted features and Vorynex cloud are optional but heavy.
- Small image: Warden needs bwrap + util-linux setpriv + strace (all small; strace is a dependency to question). Node-based npm wrapper and Next apps are excluded.
- Inconsistent version pins across docs: Axiom pins f7c9793/v0.1.17; Warden is now beta.4+ and Vorynex pins a7df7c0. Re-pin and re-verify before the ADR.

## 5. Adversarial note: how I would attack the Warden/bwrap sandbox (worth testing, none executed)
1. Symlink/TOCTOU inside granted paths: place a symlink in a writable grant pointing to ~/.ssh or /etc and have the host-side apply/diff path follow it (agent-workspace apply flow especially); also hardlinks and rename races during approval-then-apply.
2. Bind-mount/path canonicalization: grant of `./project` where project itself is a symlink or a path containing `..`/bind-mount boundary; deny globs vs case, unicode, trailing slash, `/proc/self/root`, `/proc/<pid>/cwd` inside the pid namespace.
3. Unix sockets and inherited fds: leaked fds from supervisor (audit log, strace tmp, proxy listener, credential broker socket for `warden agent`) across exec; abstract-namespace sockets (net unshared, so only inside ns); X11/Wayland/D-Bus socket accidentally mounted via runtime base or env.
4. Egress proxy abuse: HTTP CONNECT to allowed host used as a tunnel (domain fronting, allowed host that offers arbitrary relay e.g. api.github.com gists/raw), HTTP request smuggling, redirects to IP literals, DNS rebinding of an allowed name to 127.0.0.1/169.254.169.254/RFC1918 (docs say private ranges refused: test after resolve and after redirect), IPv6, port 443 vs arbitrary port allow semantics, exfil via the allowed host's own API.
5. Syscall surface without seccomp: io_uring, userfaultfd, perf_event_open, keyctl, bpf, unshare/clone3 nested namespaces despite --disable-userns, kernel LPE through the large attack surface; `--uid 0` inside userns gives fake root (test setuid binaries in the ro runtime base, CAP_SYS_ADMIN inside userns, /proc and /dev writes, mounting).
6. Audit evasion: strace is a ptrace tracer - test PTRACE-based and seccomp-based evasion, raw syscalls via io_uring (not traced by strace -e %file,%network), openat2 variations, memfd and mmap-only reads (no open), file access via inherited fd; log flooding / disk fill of audit and /tmp strace file; log injection via crafted filenames into JSONL.
7. Resource/cancel: fork bomb or grandchildren detaching from the tracked tree (docs admit), memory spike faster than the 25 ms sampler, /tmp tmpfs 64 MiB size flags, kill-on-parent-death (--die-with-parent) when supervisor is SIGKILLed vs executor cancel, zombie process leaks.
8. Policy-authoring and injection: YAML anchors/merge keys/billion-laughs, model-supplied env names (LD_PRELOAD, PATH, NODE_OPTIONS) passed through allowlist, args beginning with `-` into bwrap, command resolution of relative executables, `trace` mode unsandboxed run, `warden init` generating over-broad starter policies, HOME + ~/.ssh combos, `protect_secrets` filename heuristics evaded by renaming secrets.
9. Update/supply chain: selfupdate and npm wrapper as a downgrade/substitution vector; pin and hash the Warden binary and verify at launch.
10. For Vorynex Landlock/eBPF: memfd_create + execveat bypassing exec-dir rules, interpreter-only code, ABI-downgrade (older kernel silently handles fewer rights - verify it refuses rather than weakens), Landlock does not restrict some ops (e.g. pre-ABI4 TCP connect), eBPF-LSM program detach by a process with CAP_BPF/root.
